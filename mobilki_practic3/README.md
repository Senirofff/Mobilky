# Rally Stage Analyzer

Учебное мобильное приложение Flutter по теме «Работа с сетью». Пользователь создаёт собственные раллийные спецучастки по координатам и получает реальные погодные данные API Ninjas. Интерфейс полностью на русском, Material 3, тёмная тема с красными акцентами.

## Запуск

Нужен Flutter с Dart 3.13.2 или новее. Для Android нужны Android SDK и эмулятор либо подключённый телефон. iOS собирается на macOS с Xcode.

```powershell
cd rally_stage_analyzer
flutter pub get
flutter run --dart-define=API_NINJAS_KEY=ВАШ_КЛЮЧ
```

Ключ можно получить в личном кабинете [API Ninjas](https://api-ninjas.com/). Без ключа приложение позволяет управлять участками, а при запросе погоды показывает понятное сообщение. Реальные ключи не записывайте в код и Git. Параметр dart-define передаётся при каждой сборке; он не является защищённым серверным хранилищем секретов.

```powershell
flutter analyze
flutter test
flutter build apk --release --dart-define=API_NINJAS_KEY=ВАШ_КЛЮЧ
```

APK: `build/app/outputs/flutter-apk/app-release.apk`.

## Возможности

- **Участки:** создание, редактирование, удаление с подтверждением; локальное сохранение через shared_preferences. Широта −90…90, долгота −180…180; поддерживаются точка и запятая.
- **Анализ:** текущая погода, температура и ощущаемая температура, ветер и направление, влажность, облачность, погодная сложность; прогноз по доступным дням и трёхчасовым интервалам. Кнопка обновления принудительно запрашивает свежие данные.
- **Сравнение:** разные участки, таблица показателей и вывод по общей шкале сложности.
- **Старт:** выбор участка и доступного дня, подбор лучшего будущего интервала. При равных баллах приоритет у меньшего ветра, затем более раннего времени.

Весь прогноз и рекомендации времени отображаются в UTC. Показываются только доступные будущие интервалы, до пяти дней из ответа API; сервис может вернуть меньше данных. Отсутствующие показатели отображаются как «Нет данных», неизвестные погодные состояния не заменяются придуманными. Частичная ошибка прогноза не скрывает успешно загруженную текущую погоду.

## Сеть и зависимости

Единственный внешний источник — [API Ninjas Weather](https://api-ninjas.com/api/weather):

- `GET https://api.api-ninjas.com/v1/weather?lat=...&lon=...`
- `GET https://api.api-ninjas.com/v1/weatherforecast?lat=...&lon=...`

`dio` выполняет запросы с таймаутами. `TokenInterceptor` добавляет заголовок X-Api-Key. `pretty_dio_logger` пишет запросы, ответы и ошибки только в debug; заголовки скрыты, значение ключа дополнительно удаляется из текста логов. `get_it` регистрирует зависимости. `flutter_bloc` управляет списком участков и состоянием загрузки анализа. Простые состояния сравнения и планировщика остаются в StatefulWidget. `shared_preferences` сохраняет участки, `flutter_localizations` локализует системные элементы.

Общий WeatherService хранит ответы в памяти 10 минут, отдельно по координатам и методу, объединяет одновременные одинаковые запросы. Переключение вкладок сохраняет состояние. Изменение координат автоматически использует другой ключ кэша. Ошибки сети, доступа, лимитов и ответа сервера показываются на русском; фиктивной погоды и встроенных трасс нет.

## Правила оценки

WeatherAnalysisService использует weather и weather_description: дождь/морось +2, снег/мокрый снег +3; ветер от 6 м/с +1, от 10 м/с +2 вместо +1; температура ≤0 °C +1. Если описание одновременно указывает на снег и дождь, используется снежная категория. 0 баллов — низкая сложность, 1–2 — средняя, ≥3 — высокая. Без температуры, ветра или распознанного погодного состояния оценка недоступна. Сравнение производится по баллам, одинаковые баллы означают одинаковую погодную сложность.

Это условная учебная оценка, не профессиональный расчёт безопасности заезда.

## Структура

```text
lib/
  main.dart                   # тема, навигация, запуск
  di.dart                     # get_it и Dio
  models/                     # участок, погода и форматирование UTC
  network/token_interceptor.dart
  services/                   # сеть, хранение, оценка и подбор времени
  cubits/                     # участки и загрузка анализа
  screens/                    # четыре вкладки и форма участка
  widgets/                    # общие карточки и элементы выбора

test/                         # правила, координаты, хранение, сеть, сценарий интерфейса
```

Тесты используют изолированные ответы HTTP-адаптера и хранилище в памяти, не обращаются к API и не требуют ключа. В приложении тестовые данные не используются. Сквозную проверку реального API необходимо выполнять со своим действующим ключом. Основная целевая платформа — Android; web-оболочка также включена, но доступ браузера к API зависит от CORS сервиса.

## Проверка реализации

Выполнены `flutter pub get`, `flutter analyze` (без замечаний), `flutter test` (14 тестов), `flutter build apk --debug` и `flutter build web --release`. Проверены создание, изменение, удаление и восстановление участков, экран 360 px, погода и прогноз, сравнение, планировщик, кэш, ошибки API и отсутствие ключа. Собранный проверочный APK находится в `build/app/outputs/flutter-apk/app-debug.apk`; он собран без API-ключа. Для реальной погоды пересоберите приложение с вашим ключом по инструкции выше. iOS-проект подготовлен, сборка iOS в Windows не выполнялась.
